# 记忆知识图谱产品与技术规格

**状态：** Draft（首版交互可实施，持久语义索引契约待评审）  
**Owner：** Unassigned  
**Decision-maker：** Unknown  
**最后更新：** 2026-08-04

## 摘要

记忆总览当前用“生产关系”说明时间线如何生成文档、知识、操作和数据，但用户仍需要按时间或类型逐项查找，无法直接看见不同资产之间的主题、来源和引用联系。本方案把该说明框替换为可交互的“记忆知识图谱”，并在知识、文档、操作、数据四个 Tab 中提供类似 Obsidian 的右侧关系画布与全屏模式。

首版关系必须可解释：显式引用和共同来源直接来自现有本地字段；语义关系先使用提炼结果中的实体、主题、关键词和指标概念，后续由本地 embedding 建立持久相似边。时间只作为详情和排序辅助，不作为关系成立的依据。

## 问题与证据

### 用户问题

长期积累的记忆资产被分散在知识、文档、操作、数据四类列表中。用户知道某条内容时，仍难以回答：

- 哪些文档、操作和数据共同支持同一主题？
- 一条知识从哪些证据提炼，又被哪些资产继续使用？
- 当前内容还有哪些语义相关但时间上相隔很远的记忆？
- 从某个节点继续探索时，如何不丢失当前阅读上下文？

### 已知证据

- 用户明确要求删除总览页“生产关系”框，改为知识图谱。
- 用户明确要求图谱覆盖知识、文档、操作、数据之间的关联，不仅按时间线串联，更要按语义知识相关性串联。
- 用户提供的参考图采用文档与关系图并排的 Obsidian 式工作区，并要求图谱可展开和全屏。
- 现有本地数据已经包含 `sourceMemoryIds`、`sourceCaptureIds`、`linkedKnowledgeIds`、实体、标签、触发关键词和指标结构，可支持可解释的首版关系。

### 当前替代方案

用户只能在四个 Tab 中搜索、查看“来源与关联”字段或返回时间线逐项回溯。该方式适合验证单条来源，不适合发现跨类型、跨时间的相关内容。

## 目标与结果

- 用户能从总览直接理解个人记忆资产的主题结构和跨类型联系。
- 用户能以当前知识、文档、操作或数据为中心，展开一跳或多跳关系并继续查看相关资产。
- 每条边都能说明“为什么相关”，区分显式关系、共同来源和语义相似，避免把视觉邻近误当作事实。
- 图谱在本地完成建模、存储和展示，不改变 MemoryBread 的本地优先与隐私边界。

## 非目标

- 首版不提供用户手工编辑、合并或删除关系。
- 首版不把截图原文、完整文档正文或数据快照正文直接写入节点标签、边解释或遥测。
- 首版不建设团队共享图谱、云端图数据库或跨账户关系。
- 首版不把时间相邻视为语义相关，也不展示原始采集记录和时间线节点。
- 首版不承诺自动得出因果、依赖、冲突或真伪结论；“语义相关”只表示内容相似或概念重合。

## 用户与核心场景

### 记忆资产使用者

- 打开记忆总览，在一个画布内发现最主要的主题簇、孤立资产和跨类型联系。
- 在一份文档旁展开图谱，看到支持它的知识、可复用的操作和相关数据。
- 选中一个节点后，只突出直接邻居；继续双击或按 Enter，把该节点设为新的探索中心。
- 在关系较多时进入全屏，通过拖拽、平移、缩放和类型筛选完成探索，再退出并回到原焦点。

## 范围

### 本期范围

- 总览页以嵌入式图谱替换“生产关系”卡片。
- 知识、文档、操作、数据 Tab 提供右侧可展开图谱；图谱默认聚焦当前选中资产。
- 图谱支持全屏、退出全屏、拖拽节点、平移、缩放、适配画布、类型筛选、关系图例、悬浮解释和键盘聚焦。
- 建立统一节点与边契约，支持显式、共同来源、元数据语义和 embedding 语义四种生成来源。
- 定义空、加载、部分可用、错误和索引重建状态。

### 后续范围

- 用户手工确认、隐藏或新增关系。
- 关系时间演化、历史版本对比和冲突知识提示。
- 社区发现、主题自动命名和跨设备加密同步图谱。

## 术语与关系模型

### 节点类型

| 用户可见名称 | `kind` | 稳定 ID 格式 | 主要语义字段 |
| --- | --- | --- | --- |
| 知识 | `knowledge` | `knowledge:{id}` | 摘要、概述、分类、实体 |
| 文档 | `document` | `document:{id}` | 标题、摘要、标签、章节关键词 |
| 操作 | `operation` | `operation:{id}` | 问题、步骤摘要、触发关键词 |
| 数据 | `data` | `data:{id}` | 数据标题、摘要、标签、指标与维度 |

节点 ID 必须使用类型前缀，避免不同本地表的数字或字符串 ID 冲突。

### 关系类型

| 用户可见名称 | `relation_type` | 方向 | 成立依据 | 默认视觉 |
| --- | --- | --- | --- | --- |
| 提炼自 | `derived_from` | 有向 | 资产记录了另一个资产的稳定来源 ID | 深灰实线箭头 |
| 引用了 | `references` | 有向 | 文档或操作显式记录关联知识 ID | 深灰实线箭头 |
| 共同来源 | `shared_source` | 无向 | 两个资产共享时间线或采集证据 | 中性灰实线 |
| 语义相关 | `semantic` | 无向 | 提炼概念重合或 embedding 相似度达到阈值 | 系统蓝虚线 |

时间戳不得单独生成边。每条 `semantic` 边必须包含分数、强度和用户可理解的证据摘要；embedding 相似但无法形成安全摘要时可显示“内容主题相近”，不得展示模型名或原始向量。

## 功能需求

- **FR-001** — 当用户打开记忆总览时，产品必须移除“生产关系”说明框，并在同一信息层级展示覆盖知识、文档、操作和数据的全局关系图谱。
- **FR-002** — 当用户位于知识、文档、操作或数据 Tab 时，产品必须提供“关系图谱”开关；展开后在不离开当前 Tab 的情况下显示右侧关系画布。
- **FR-003** — Tab 内图谱展开时，产品必须把当前选中资产设为聚焦节点，并突出它的一跳邻居；切换列表选中项时图谱必须同步聚焦。
- **FR-004** — 图谱必须支持节点拖拽、画布平移、滚轮或触控板缩放、适配画布和全屏查看；退出全屏后必须保留当前聚焦节点。
- **FR-005** — 用户悬浮、键盘聚焦或选中一条关系时，产品必须显示关系类型、强度以及“为什么相关”的解释，不得仅用距离或颜色暗示关系。
- **FR-006** — 用户激活图谱节点时，产品必须在对应的知识、文档、操作或数据 Tab 打开该资产；若资产已被删除，必须刷新图谱并提示“该内容已不存在”。
- **FR-007** — 产品必须允许按四类节点筛选显示范围，并提供显式关系、共同来源和语义关系的可区分图例；筛选不得删除底层关系数据。
- **FR-008** — 图谱数据必须优先保留显式引用和共同来源关系，再按语义分数选择每个节点的有限邻居；不得因为展示上限丢弃当前聚焦节点或它的显式一跳邻居。
- **FR-009** — 当语义索引尚未就绪或正在重建时，产品必须继续展示可用的显式和共同来源关系，并明确标记“语义关联构建中”或“当前仅展示已确认关系”。
- **FR-010** — 当没有可展示节点时，产品必须展示引导空状态；当存在节点但没有关系时，必须展示孤立节点并解释“继续积累或完成语义索引后会出现关联”。
- **FR-011** — 删除、更新或重新提炼资产后，产品必须使相关节点和边最终与当前资产状态一致；已删除节点不得继续出现在新图谱响应中。
- **FR-012** — 关系生成必须在本机完成并持久化稳定结果；客户端不得接收供应商模型名、供应商密钥、购买成本或原始向量。
- **FR-013** — 产品必须为每条关系保留生成来源：`explicit`、`shared_source`、`semantic_metadata` 或 `semantic_embedding`，用于解释、重建和降级。
- **FR-014** — 产品必须避免仅因创建时间接近而生成关系；时间只可用于排序、详情和同分关系的稳定裁决。

## 非功能需求

- **NFR-001** — 隐私：节点标签和边解释必须使用已提炼摘要、实体、标签、关键词和指标名；不得把截图路径、Cookie、完整快照正文或敏感采集文本写入图谱契约和日志。
- **NFR-002** — 可访问性：所有图谱操作必须有可见键盘焦点；节点可通过 Tab 聚焦、Enter 激活，Escape 退出全屏；颜色不得是区分节点或关系类型的唯一方式。
- **NFR-003** — 动效：系统启用 `prefers-reduced-motion` 时，图谱不得执行持续布局动画或非必要过渡。
- **NFR-004** — 稳定性：同一图谱版本、相同查询和相同节点集合必须得到稳定的初始布局，避免每次打开完全重排。
- **NFR-005** — 兼容：首版不得新增必须联网的运行时依赖；现有本地数据库升级后，旧资产在语义边完成回填前仍可通过显式关系显示。

## 交互与视觉规格

### 设计方向

图谱直接沿用当前记忆页的简约设计系统：纯白画布和卡片、浅灰页面背景、深色正文、细灰边框与克制阴影，交互选中和键盘焦点使用现有系统蓝。四类节点复用记忆总览趋势图的知识绿、文档橙、操作紫、数据粉，同时使用形状和字母缩写辅助辨识；显式关系使用深灰实线，共同来源使用中性灰实线，语义关系使用系统蓝虚线，避免只靠颜色传达含义。不得引入暖白画布、深棕文字或烘焙橙主题，也不增加装饰性渐变。

### 总览布局

```text
┌ 记忆总览统计 ────────────────────────────────────────┐
├ 记忆生产历程（保留时间趋势，只表达数量变化）──────────┤
├ 知识图谱 ────────────────────────────────────────────┤
│ [全部][知识][文档][操作][数据]     [适配] [全屏]      │
│                                                     │
│              可平移 / 缩放 / 拖拽的关系画布           │
│                                                     │
│  图例：提炼/引用 ━  共同来源 ─  语义相关 ┄             │
└─────────────────────────────────────────────────────┘
```

### Tab 布局

```text
关闭图谱：┌ 列表 ─────────┬ 当前资产详情 ───────────────┐ [关系图谱]

展开图谱：┌ 列表/详情工作区 ──────────┬ 关系图谱 ───────┐
          │ 当前选择保持不变           │ 聚焦当前节点     │
          │                            │ [适配][全屏][×]  │
          └────────────────────────────┴─────────────────┘
```

在窄窗口中，展开图谱改为覆盖式右侧抽屉；全屏始终覆盖应用内容区而不是打开新系统窗口。

### 关键状态

- **加载：** 保留画布轮廓和工具栏，显示“正在整理关系…”，不显示伪造节点。
- **空资产：** “还没有可连接的记忆资产。先从时间线提炼知识、文档、操作或数据。”
- **无关系：** 展示当前孤立节点，并说明“已找到内容，但暂未发现可靠关联”。
- **部分可用：** 显式关系正常显示，工具栏展示“语义关联构建中”。
- **错误：** 保留当前内容阅读区域；图谱区域说明失败原因并提供“重新加载”。
- **节点过多：** 默认保留聚焦节点、显式一跳邻居和每节点高分语义邻居；显示“已展示最相关的 N/M 项”。

## 接口与契约

### 查询

`GET /api/bake/graph`

查询参数：

| 参数 | 必填 | 语义 |
| --- | --- | --- |
| `scope` | 否 | `global` 或 `focus`，默认 `global` |
| `focus_kind` | focus 时是 | `knowledge` / `document` / `operation` / `data` |
| `focus_id` | focus 时是 | 资产表中的稳定 ID，不含类型前缀 |
| `depth` | 否 | `1` 或 `2`，默认 `1` |
| `limit` | 否 | 展示节点上限；服务端必须先保留 FR-008 规定的节点 |
| `min_semantic_score` | 否 | 语义边最低分；缺省值由稳定图谱版本决定 |

响应示例仅用于说明字段，不构成真实数据承诺：

```json

  "generated_at": 1785800000000,
  "index_status": "ready",

    "indexed_nodes": 116,
    "returned_nodes": 64,
    "returned_edges": 92
  },
  "nodes": [
    {
      "id": "knowledge:18",
      "kind": "knowledge",
      "asset_id": "18",
      "label": "GPU 利用率口径",

  ],

    }
```

### 字段约束

- `schema_version` 只在不兼容字段语义变化时升级。
- `graph_version` 在节点或边集合变化时更新，用于稳定布局和缓存失效。
- `score` 取值 `[0, 1]`；显式关系可省略分数，客户端不得把不同生成来源的分数直接横向排序。
- `evidence_summary` 必须是安全、简短、用户可理解的解释；不得包含原始向量和完整正文。
- `semantic_index_version` 可仅在服务端和本地存储中使用；客户端不得看到具体供应商或购买信息。

### 错误与降级

| HTTP / 错误码 | 条件 | 客户端行为 |
| --- | --- | --- |
| `400 GRAPH_INVALID_FOCUS` | focus 参数缺失或类型非法 | 保留当前页面并提示无法定位节点 |
| `404 GRAPH_NODE_NOT_FOUND` | 聚焦资产已删除 | 刷新列表和图谱，提示内容已不存在 |
| `200 index_status=building` | embedding 回填中 | 展示显式/共同来源/元数据语义边和构建提示 |
| `200 index_status=degraded` | embedding 暂不可用 | 展示已有可靠边和降级提示 |
| `500 GRAPH_STORAGE_ERROR` | 本地存储不可读 | 图谱显示重试入口，不影响资产列表与详情 |

## 关系生成与生命周期

1. 资产创建或更新时，核心服务同步更新节点快照和显式关系。
2. 从 `sourceMemoryIds`、`sourceCaptureIds`、`linkedKnowledgeIds` 等稳定字段生成 `derived_from`、`references` 和 `shared_source` 边。
3. 从实体、分类、标签、章节关键词、触发关键词、数据指标和维度生成可解释的 `semantic_metadata` 候选边。
4. sidecar 在本地 embedding 可用时异步向量化新的或变更的资产，按稳定阈值和每节点 Top-K 生成 `semantic_embedding` 边。
5. 同一节点对同时存在多种依据时保留一条用户可见主边，并在内部 `evidence` 中合并依据；显式关系优先于语义关系。
6. 资产软删除、硬删除或内容版本变化时，使旧边失效并进入幂等重建；重建失败保留最后一次成功关系并标记版本过期。
7. 阈值或 embedding 版本变化时以新图谱版本全量回填；完成前旧版本继续只读，完成后原子切换。

建议本地持久表（名称待工程评审）：

- `memory_graph_nodes(node_id, kind, asset_id, content_hash, concepts_json, updated_at, deleted_at)`
- `memory_graph_edges(edge_id, source_node_id, target_node_id, relation_type, generation_source, score, strength, evidence_json, graph_version, updated_at)`
- `memory_graph_jobs(asset_kind, asset_id, content_hash, status, attempts, next_retry_at, last_error_code)`

## 验收标准

- **AC-001** — 验证 **FR-001**。给定四类资产至少各一条，打开记忆总览后，不再出现“生产关系”标题，并在原位置看到包含四类节点和关系图例的图谱。
- **AC-002** — 验证 **FR-002**。分别进入知识、文档、操作、数据 Tab，点击“关系图谱”后，页面在当前 Tab 内展开右侧画布，再次关闭后恢复原工作区。
- **AC-003** — 验证 **FR-003**。给定列表中选中资产 A，展开图谱后 A 为聚焦节点；再选择资产 B，图谱在不关闭的情况下改为聚焦 B 并突出 B 的直接邻居。
- **AC-004** — 验证 **FR-004**。展开含多个节点的图谱，拖动节点、平移、缩放并进入全屏均生效；按 Escape 退出全屏后仍聚焦原节点。
- **AC-005** — 验证 **FR-005**。聚焦语义边后可见“语义相关”、强度和概念解释；聚焦共同来源边后可见共同证据说明，且二者线型不同。
- **AC-006** — 验证 **FR-006**。从图谱激活另一类型的有效节点后打开对应 Tab 和资产；删除该资产后再次激活，图谱移除节点并出现“该内容已不存在”提示。
- **AC-007** — 验证 **FR-007**。关闭任一节点类型筛选后，对应节点和仅依赖它的边从画布隐藏；重新启用后恢复，图例始终可读。
- **AC-008** — 验证 **FR-008**。给定超过展示上限的图谱，响应仍包含聚焦节点、它的全部显式一跳邻居，并只裁剪低优先级语义邻居。
- **AC-009** — 验证 **FR-009**。模拟语义索引 `building` 与 `degraded`，显式和共同来源关系仍可交互，工具栏分别显示构建中和降级提示。
- **AC-010** — 验证 **FR-010**。无资产时显示提炼引导；只有一个无边节点时显示孤立节点和可靠关联尚未形成的说明。

## 度量与可观测性

- **OBS-001** — 本地事件 `memory_graph_opened`：入口（overview/tab）、节点数、边数、是否全屏；不记录节点标题、摘要和资产 ID，用于判断功能是否被发现。
- **OBS-002** — 本地事件 `memory_graph_node_activated`：来源类型、目标类型、跳数；不记录内容，用于判断跨类型探索是否发生。
- **OBS-003** — 本地指标 `graph_index_coverage`：可索引节点数、已索引节点数、失败任务数和最后成功时间，用于诊断构建状态。
- **OBS-004** — 本地指标 `graph_query_duration_ms` 与裁剪前后节点/边数量，用于确定默认上限；是否上报匿名聚合数据属于开放决策，默认不上云。

## 发布、迁移与回滚

- **ROLL-001** — Slice A：发布前端可解释图谱，使用现有显式来源与提炼元数据；通过功能开关控制，总览替换和 Tab 展开使用同一组件。关闭开关即可恢复旧页面布局，不删除资产数据。
- **ROLL-002** — Slice B：新增本地节点/边/job 表与 `/api/bake/graph` 兼容接口，先回填显式和共同来源边；验证节点删除、幂等更新和旧库迁移。
- **ROLL-003** — Slice C：sidecar 影子生成 embedding 边但不展示，与元数据关系做离线对比；达到评审标准后再切换为可见，异常时回退到显式与元数据边。
- **ROLL-004** — 回滚不得删除已生成节点和边表；旧客户端忽略新表，新客户端在接口不可用时把图谱区域降级为可重试状态，资产列表与详情保持可用。

## 风险与缓解

- **错误关联降低信任。** 语义边必须展示解释；高阈值、每节点 Top-K 和显式关系优先；后续提供隐藏/确认关系。
- **图谱过密不可读。** 默认只显示最相关节点，聚焦时淡化非邻居，提供类型筛选和适配画布。
- **页面性能受大图影响。** 服务端裁剪、稳定布局、非全屏限制节点数；具体节点上限与耗时目标待基准测试后确认。
- **删除后残留关系。** 用内容哈希、删除触发和幂等重建保证最终一致，并对过期版本显式标记。
- **敏感内容进入解释。** 只使用已提炼概念生成标签与解释，执行隐私过滤，遥测不含内容和资产 ID。
- **现有未提交改动冲突。** 首版尽量新增独立组件和工具，仅在 `BakePanel`、总览和公共样式做窄范围接入。

## 开放问题与决策

- 是否允许用户手工隐藏、确认或新建关系？影响边的生命周期与审计模型，当前不在首版。
- 全局图默认节点上限、聚焦图 Top-K 和 embedding 分数阈值是多少？需用真实本地库做性能与准确性基准后决定。
- 节点激活采用单击预览、双击打开，还是单击直接打开？首版建议单击聚焦、Enter/双击打开，待可用性验证。
- 匿名使用聚合是否允许上报？默认仅保存在本地，需单独隐私决策后才能改变。
- embedding 边是覆盖元数据语义边，还是并列保留多证据？建议用户可见合并、内部保留多证据，待数据结构评审。
